# Плагин NTTS

[English version](README.EN.md)

Java-интеграция между [/N/TTS](https://ntts.fdev.team/) и [Simple Voice Chat](https://modrinth.com/plugin/simple-voice-chat). Сервер преобразует сообщения игрового чата в речь и воспроизводит её для всех игроков либо рядом с отправителем.

Готовые файлы выпускаются для **Fabric** и **Forge**. Simple Voice Chat должен быть установлен как на сервере, так и у клиентов.

## Настройка

При первом запуске мод создаёт файл `config/ntts.properties`:

```properties
enabled=true
token=
mode=global
voice_mode=static
default_speaker=narrator_d3
effect=
allow_player_effects=true
max_text_length=300
```

Токен можно получить на [странице /N/TTS в Boosty](https://boosty.to/ntts). Укажите его в файле или, что предпочтительнее, через переменную окружения `NTTS_TOKEN`. Если токен не задан, NTTS остаётся безопасно отключённым.

Режимы воспроизведения:

- `global` — сгенерированное сообщение слышат все подключённые игроки.
- `local` — речь исходит от отправителя и слышна в радиусе 16 блоков.

Режимы выбора голоса:

- `static` — используется сохранённый выбор игрока, а при его отсутствии — `default_speaker`.
- `random` — каждому игроку назначается случайный доступный голос до следующей перезагрузки; если список голосов недоступен, используется `default_speaker`.

Игрок выбирает голос командой `/set_speaker <speakerID>`, а необязательный эффект — командой `/set_effect <effect|none>`. Обе команды показывают нечётко ранжированные подсказки во время ввода. Поиск голоса учитывает название голоса, идентификатор диктора и части, разделённые пробелами или символами подчёркивания. Выбор сохраняется в `config/ntts_speaker_data.json` и `config/ntts_effect_data.json`. Параметр `effect` в основном конфиге задаёт эффект по умолчанию.

При `allow_player_effects=false` игроки не могут выбирать собственные эффекты, и применяется только серверный эффект по умолчанию. Сохранённый выбор игроков не удаляется и снова применяется после включения параметра. Пока NTTS включён, подходящие сообщения чата озвучиваются автоматически. Индивидуальная громкость и отключение звука управляются средствами Simple Voice Chat.

## Команды оператора

- `/ntts status` — безопасная информация о провайдере, очереди, лимитах и использовании без вывода токена.
- `/ntts enable` и `/ntts disable` — временное включение или отключение во время работы сервера.
- `/ntts reload` — повторная загрузка конфигурации и `NTTS_TOKEN`.
- `/ntts get <key>` — просмотр безопасного параметра конфигурации.
- `/ntts set <key> <value>` — сохранение безопасного параметра и перезагрузка конфигурации. Токен нельзя читать или изменять командами.
- `/ntts reset <key|all>` — восстановление стандартных значений без изменения токена.
- `/ntts test` — генерация тестовой фразы голосом выполняющего команду игрока.
- `/ntts say <message>` — голосовое объявление от имени оператора; команда должна выполняться игроком.
- `/ntts player inspect <player>` — просмотр эффективного голоса, эффекта, переопределения и блокировки игрока.
- `/ntts player voice set <targets> <speaker>` — назначение голоса выбранным игрокам.
- `/ntts player voice reset <targets>` — сброс назначенного и личного голоса выбранных игроков.
- `/ntts player voice lock|unlock <targets>` — запрет или разрешение самостоятельного изменения голоса.
- `/ntts queue clear` — очистка очереди синтеза.

Ключи и допустимые значения для `/ntts get`, `/ntts set` и `/ntts reset` имеют нечётко ранжированное автодополнение. Административные команды поддерживают селекторы игроков, но одна массовая операция ограничена 100 целями. Действия записываются в журнал сервера, а затронутые игроки получают уведомления. Переопределения и блокировки сохраняются в `config/ntts_player_admin.json`.

Синтез выполняется в ограниченной асинхронной очереди, а аудио хранится в ограниченном по памяти кэше. Метаданные токена используются для локального соблюдения лимита символов, частоты запросов, квоты и срока действия. Ограничение частоты со стороны провайдера считается обычной обратной нагрузкой: соответствующее аудио пропускается без отключения NTTS.

## Поддерживаемые версии Minecraft

Список версий находится в [`versions/supported.txt`](versions/supported.txt). Для каждой версии существует файл параметров в каталоге [`versions/`](versions/) с версиями Java, Fabric, Forge и зависимостей.

Поддерживаемые версии:

- 1.19.2
- 1.20.1
- 1.21.1
- 1.21.4
- 1.21.5
- 1.21.8
- 1.21.11
- 26.1.2
- 26.2

Для полной локальной сборки установите JDK 21 и JDK 25 или 26. `scripts/build.sh` автоматически выбирает подходящую Java для каждого поколения Gradle. Если JDK установлены в нестандартных каталогах, можно использовать `JAVA_HOME_21_X64` и `JAVA_HOME_25_X64`.

```bash
scripts/build.sh                         # Fabric + Forge для всех версий
scripts/build.sh fabric                  # Fabric для всех версий
scripts/build.sh forge 1.20.1            # Forge для Minecraft 1.20.1
scripts/build.sh 1.21.11                 # Fabric + Forge для Minecraft 1.21.11
scripts/build.sh all all 1.1.0           # полная сборка с указанной версией мода
```

Готовые JAR-файлы записываются в каталог `dist/`.

### Добавление поддерживаемой версии

1. Добавьте `versions/<minecraft-version>.properties`.
2. Добавьте версию в `versions/supported.txt`.
3. Запустите `scripts/build.sh` и адаптируйте изменения API Minecraft при необходимости.

Отдельная ветка для каждой версии Minecraft не требуется. Профили до 1.21.8 включительно используют поколение `doggyman`, версия 1.21.11 — `ping_9/`, а версии 26.x — `unlimited_damage/`. Скрипт сборки автоматически выбирает нужное поколение.

## CI/CD

[`.github/workflows/build-and-release.yml`](.github/workflows/build-and-release.yml) собирает полную матрицу версий при отправке изменений и в pull request, после чего загружает JAR-файлы как артефакты GitHub Actions.

Отправка тега версии создаёт GitHub Release со всеми сборками Fabric и Forge:

```bash
git tag v1.1.0
git push origin v1.1.0
```

Версия из тега записывается в выпускаемые JAR-файлы, поэтому отдельный коммит с изменением `gradle.properties` перед выпуском не требуется.
